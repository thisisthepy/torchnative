# `linear` 의 호출당 가중치 복사 — 비트는 바뀌었고, 바뀐 방향은 전부 상류 쪽입니다

측정일 2026-08-29. 브랜치 `work/linear`. 호스트 Apple M1 (P 4 + E 4, macOS darwin 25.5.0),
CPython 3.13.0, 상류 torch 2.13.0, candle-core 0.11.0, Accelerate 켜짐.
**벤더링 트리는 한 줄도 고치지 않았습니다.** 기기·시뮬레이터는 쓰지 않았습니다.
측정 내내 load average 는 **1.4 ~ 2.0** 이었고, 각 표 앞뒤로 기록했습니다.

`docs/DESIGN.md` "열려 있는 성능 결함" 과 `docs/QUANT2.md` §6 이 이름을 붙여두고
"고치지 않았다, 그것이 판단이다" 로 닫아둔 자리입니다.

## 0. 첫 줄 — 비트가 바뀌었습니까

**바뀌었습니다.** 507 개 커널 케이스 중 **48 개**의 결과가 배송본과 비트 단위로 다릅니다.

그런데 **다른 방향이 한쪽뿐입니다.**

| | 상류 torch 와 비트 일치 | 상류와 불일치 |
|---|---:|---:|
| 배송본 | 335 | 172 |
| 이 변경 | **370** | 137 |

- **상류와 일치하던 것이 어긋난 케이스: 0 개.**
- **어긋나 있던 것이 일치하게 된 케이스: 35 개.**

즉 이것은 `docs/SDPA.md` §12 가 옵트인으로 가른 종류의 맞바꿈 — "정확성을 내주고 속도를
받는다" — **이 아닙니다.** 상류와의 비트 일치를 잃은 케이스가 하나도 없습니다.

**다만 "전부 좋아졌다" 는 아닙니다.** 어느 쪽도 상류와 일치하지 않던 케이스 중 3 개는
상류로부터 **수치적으로 조금 멀어졌습니다** — 전부 `2×3×4×5` 짜리 장난감 `bmm`/`baddbmm`
이고 `2.4e-7 → 4.8e-7` 로 한 ULP 급입니다 (§4.2). **그리고 비트는 어쨌든 바뀌었으므로**,
착지 여부의 판단은 §7 에 선택지로 정리하고 여기서 임의로 고르지 않았습니다.

**SmolLM2-135M 수준에서는 비트가 아예 안 바뀝니다.** 프리필 로짓 294,912 개가
**한 개도 다르지 않고**(0/294912), 생성 20 토큰이 상류와 20/20 일치하는 것도 그대로입니다.
그러면서 **프리필 4.35 배, 토큰당 3.69 배** 빨라집니다 (§5).

## 1. 원인이 하나가 아니었습니다

지시받은 진단은 "`aten.rs` 의 `.contiguous()` 두 줄" 이었습니다. 그것은 **맞지만 절반입니다.**
같은 복사를 하는 자리가 하나 더 있고, **그쪽이 실모델이 지나가는 자리**입니다.

```python
# rust/torch_c/src/bootstrap.py  linear()
wt = _t(weight)                                   # 전치 "뷰" -- 공짜
return dispatch("aten.matmul.default", input, wt)
```

### 1-A. 우리가 부르던 복사

```rust
// aten.rs  matmul_default / addmm_default / bmm_default / baddbmm_default
lhs.tensor()?.fast_to(acc).and_then(|l| l.contiguous())      // <- 무조건
```

### 1-B. candle 이 부르는 복사

`matmul_default` 는 `broadcast_matmul` 을 부릅니다. 그 안이 이렇습니다.

```rust
// candle-core-0.11.0  tensor.rs:1550
// TODO: Avoid concretising the broadcasted matrixes via contiguous.
(false, true) => lhs.matmul(&rhs.broadcast_as(&r_shape)?.contiguous()?),
```

`linear` 에 들어오는 활성값은 `(batch, seq, hidden)` 이라 **랭크가 3** 이고, 가중치 전치본은
**랭크 2** 입니다. 랭크가 다르므로 `r_broadcast = true` 가 되어 **가중치가 여기서 복사됩니다.**
1-A 를 지워도 이쪽은 그대로입니다.

**그래서 1-A 만 고치면 실모델은 1 밀리초도 안 빨라집니다.** 측정입니다 —
`lm_head` (49152×576) 에 전치 뷰를 넘겼을 때:

| 활성값 랭크 | 배송본 | 1-A 만 | 1-A + 1-B | 상류 |
|---|---:|---:|---:|---:|
| `(6, 576)` 2-D | 85.6 ms | **4.71 ms** | 4.75 ms | 4.64 ms |
| `(1, 6, 576)` 3-D | 85.8 ms | **88.3 ms** | **4.76 ms** | 4.75 ms |

3-D 행이 이 문서의 핵심입니다. `docs/QUANT2.md` §6.2 의 표는 2-D 로 쟀기 때문에
이 두 번째 복사가 보이지 않았습니다.

**SmolLM2-135M 의 한 번 순전파에서 `F.linear` 은 211 회 불리고, 활성값이 3-D 가 아닌 것은
하나도 없습니다** (계측):

| 활성값 | 가중치 | 횟수 |
|---|---|---:|
| `(1, 6, 576)` | `(576, 576)` q/o_proj | 60 |
| `(1, 6, 576)` | `(192, 576)` k/v_proj | 60 |
| `(1, 6, 576)` | `(1536, 576)` gate/up_proj | 60 |
| `(1, 6, 1536)` | `(576, 1536)` down_proj | 30 |
| `(1, 6, 576)` | `(49152, 576)` lm_head | 1 |

> **1-A 는 단독으로 착지시키면 안 됩니다.** 배치가 있는 3-D 에서는 **느려집니다** —
> 배송본은 전치본을 먼저 연속으로 만든 뒤 `broadcast_as` 하지만, 1-A 만 적용하면
> candle 이 **전치 레이아웃 위에서** 스트라이드 수집을 배치 수만큼 합니다.
> `lm_head` × `(4, 512, 576)` 에서 253.2 ms → **473.6 ms** (1.87 배 느림).
> 두 변경은 분리할 수 없습니다.

## 2. candle 은 비연속 피연산자를 원래 받습니다 — 어디까지인지

`.contiguous()` 가 낭비였는지부터 확인했습니다. 두 CPU 백엔드 모두 `lhs_l.stride()` 와
`rhs_l.stride()` 를 읽어 곱셈에 그대로 넘깁니다.

| 백엔드 | 마지막 두 차원 | 거절하는 것 |
|---|---|---|
| Accelerate / MKL (`cpu_backend/mod.rs`) | 스트라이드에서 `transa`/`transb` 를 고름. **전치 뷰 = `CblasTrans`** | 그 둘 중 어느 쪽도 아닌 레이아웃 → `MatMulUnexpectedStriding` |
| `gemm` (Apple 아닌 전 타깃) | `lhs_cs`/`lhs_rs`/`rhs_cs`/`rhs_rs` 를 그대로 전달 | 마지막 두 차원은 **임의 스트라이드 허용** |

즉 `linear` 이 만드는 전치 뷰는 **Accelerate 가 원래 받는 모양**입니다. 복사는 순수 낭비였습니다.

둘이 공유하는 `MatMul::ab_skip` 은 **배치** 스트라이드가 네 가지 중 하나여야 하고 아니면
거절합니다 — 랭크 4 이상에서 배치 축 둘을 맞바꾼 경우가 여기 걸립니다.

**받는 집합이 백엔드마다 다르고 랭크마다 다릅니다.** 그래서 그 술어를 우리 쪽에 옮겨 적지
않았습니다. 옮겨 적으면 candle 과 동기화를 유지해야 하고, **관대한 방향으로 틀리면 그것은
실패가 아니라 틀린 답**입니다. 대신 물어보고, 거절할 때만 복사합니다:

```rust
match multiply(lhs, rhs) {
    Err(e) if is_matmul_striding_refusal(&e) => multiply(&lhs.contiguous()?, &rhs.contiguous()?),
    other => other,
}
```

이 방향으로는 틀릴 수 없습니다. 곱셈에 도달하는 레이아웃은 **정확히 candle 이 받는 것들**이고,
못 받는 것이 조용히 통과하는 경로가 없습니다. `MatMulUnexpectedStriding` 은 양쪽 백엔드 모두
**목적지 버퍼를 잡기 전에** 나오므로, 거절당한 시도의 비용은 스트라이드 검사 하나입니다
(§4 에서 측정: 0.98 ~ 1.02 배, 잡음 안).

**`aten.mm.default` 는 원래부터 `.contiguous()` 를 부르지 않았습니다.** "candle 이 스트라이드
피연산자를 받는다" 는 이미 배송 중이었고 골든이 비교해 온 것입니다. 새로 생긴 것은 폴백과
나머지 네 커널입니다.

## 3. 무엇을 고쳤는가

`rust/torch_c/src/aten.rs` 한 파일, 115 줄 추가 · 16 줄 삭제.

| # | 무엇 | 어디 |
|---|---|---|
| A | 무조건 `.contiguous()` 제거, candle 이 거절할 때만 복사 | `matmul` · `addmm` · `bmm` · `baddbmm` (`gemm_with_layout_fallback`) |
| B | 오른쪽이 2-D 면 배치를 행으로 접어 **2-D GEMM 한 번**. 브로드캐스트하지 않음 | `matmul` (`batched_matmul`) |

B 는 발명이 아니라 **상류가 하는 것**입니다. `at::native::matmul` 은 오른쪽이 2-D 일 때
브로드캐스트하지 않고 접고, `at::native::linear` 의 bias 없는 N-D 갈래는
`t, view, mm, _unsafe_view` 입니다 — `bootstrap.py::_install_nn` 이 이미 주석으로
전사해 둔 그 목록입니다.

접기가 근사가 아닌 이유: 오른쪽이 2-D 면 **모든 배치 원소가 같은 행렬을 곱하므로**, 행을
쌓아 한 번 곱한 것과 배치로 나눠 곱한 것이 같은 내적 집합입니다. 오른쪽이 2-D 이고 왼쪽이
더 높을 때만 발동하고, 나머지 모양은 전부 `broadcast_matmul` 로 갑니다 — 브로드캐스트
의미론은 그대로입니다.

**`_quantized_linear` 는 건드리지 않았습니다.** 벤더링 트리도 그대로입니다.

## 4. 비트 — 507 케이스, 네 갈래 대조

`bitprobe.py` 가 같은 케이스 목록을 **배송본 · A · A+B · 상류 torch** 넷에 돌립니다.
케이스는 모양(작은 것부터 `lm_head` 49152×576 까지) × dtype(`float32`/`float64`/`bfloat16`/`float16`,
정수 2 종) × **레이아웃**(연속 · 전치 뷰 · 스트라이드 슬라이스 · 배치 축 교환 · 브로드캐스트) ×
연산(`matmul`/`mm`/`addmm`/`bmm`/`baddbmm`) 입니다. 다이제스트는 전 원소의 IEEE 비트에 대한
sha256 이라 **허용오차가 아니라 비트 비교**입니다.

| | 상류와 일치 | 배송본과 일치 |
|---|---:|---:|
| 배송본 | 335 / 507 | — |
| A | 359 (+24, **후퇴 0**) | 483 |
| **A+B** | **370 (+35, 후퇴 0)** | 459 |

### 4.1 바뀌지 않는 것 — 그리고 왜

- **`bfloat16` · `float16` 은 한 케이스도 안 바뀝니다.** `opmath_in` 이 상류를 따라 `float32`
  로 넓히는데(`docs/BF16.md`), 그 `to_dtype` 이 **이미 연속 텐서를 만들어 놓습니다.**
  뒤따르던 `.contiguous()` 는 그 dtype 들에서는 처음부터 no-op 이었습니다.
- **`aten.mm.default` 도 안 바뀝니다** — 원래 `.contiguous()` 가 없었으므로. 대조군입니다.
- **연속 피연산자는 안 바뀝니다** — `contiguous()` 는 이미 연속이면 clone 이므로 레이아웃이
  같습니다. 바뀔 수 있는 것은 **비연속 피연산자가 실제로 있던 케이스**뿐입니다.
- 정수 dtype 은 양쪽 다 `unsupported dtype I64 for op matmul` 로 거절합니다 (candle 에 정수
  matmul 커널이 없음, 기존 그대로).

즉 바뀌는 것은 **`float32`/`float64` × 전치(또는 접기) 경로**뿐입니다.

### 4.2 얼마나 다른가

바뀐 케이스의 크기입니다 (초기 414 케이스판에서 배송본 대 A 로 바뀐 36 개를 원소별로 대조):

| | 최대 상대차 | 상류와의 최대 절대차 (배송본 → A) |
|---|---|---|
| `float32` | ≤ 1.2 e-6 | 예: `lm_head` 1×576×49152 `1.183e-4` → **0.0** |
| `float64` | ≤ 3.7 e-16 | 예: `gate` 1×576×1536 `2.842e-14` → **0.0** |

전부 그 dtype 의 마지막 비트 수준입니다. 방향은 §0 의 표대로 상류 쪽입니다. 개별 케이스에서
상류로부터 **멀어진** 것은 3 개뿐인데, 전부 `2×3×4×5` 짜리 장난감 `bmm`/`baddbmm` 이고
`2.4e-7 → 4.8e-7` (한 ULP 급)이며 **어느 쪽도 상류와 일치하지 않던** 케이스입니다.

> **이 표가 뜻하지 않는 것.** 배송본이 상류와 172/507 어긋나 있는 것은 **이 변경이 만든 것이
> 아닙니다.** 이 프로브는 골든보다 훨씬 깊은 리덕션(k = 576 · 1536)을 쓰고, 그 깊이에서
> BLAS 블로킹 차이로 이미 어긋나 있던 것입니다. 골든 2760 개는 케이스가 작아 전부 통과합니다.

### 4.3 골든이 `matmul` 을 안 봅니다

`aten.matmul.default` 는 `_aten_implemented()` 가 아니라 **`IMPLEMENTED_AWAITING_GOLDEN`**
에 있습니다. 즉 **골든 2760 개는 `matmul` 을 한 케이스도 비교하지 않습니다.**
`mm`/`bmm`/`addmm`/`baddbmm` 은 비교합니다.

**"골든 2760/2760 통과" 는 이 변경의 근거가 될 수 없고**, §4 의 프로브가 그 자리를 메우려고
쓴 것입니다. `tools/golden/cases.py` 에 `matmul` 케이스 빌더를 넣는 것이 남은 일입니다.

## 5. 속도

### 5.1 커널 — 한 프로세스 안에서 넷을 교대 (load 1.58 → 1.89)

| **`matmul` 열 스트라이드 2** 128×1024×1024 | 1.0791 | 1.0646 | 1.01× |
| **`matmul` 4-D 배치축 교환** 4×8×64×64 | 0.0544 | 0.0556 | 0.98× |
| `bmm` 연속 12×128×64×128 | 0.0336 | 0.0339 | 0.99× |
| **`bmm` 전치뷰** 12×128×64×128 | 0.2479 | **0.0426** | 5.82× |
| **`baddbmm` 전치뷰** 12×128×64×128 | 0.2577 | **0.0528** | 4.88× |
| **`bmm` 전치뷰** 32×33×64×33 | 0.1698 | **0.0362** | 4.70× |
| **`baddbmm` 전치뷰** 32×33×64×33 | 0.1746 | **0.0434** | 4.02× |

**거절당한 시도의 비용은 잡음 안입니다** (0.98 ~ 1.02×) — candle 이 목적지를 잡기 전에
스트라이드를 검사하기 때문입니다. 그리고 어텐션 모양의 `bmm`/`baddbmm` 이 전치 피연산자에서
**4 ~ 5.8 배** 빨라집니다. 이것은 `linear` 과 별개의 이득입니다.

### 5.3 모델 — SmolLM2-135M, `dtype=torch.float32`, 그리디 20 토큰

`HuggingFaceTB/SmolLM2-135M`, 프롬프트 `[1, 4380, 314, 260, 3387, 286]` (`docs/GENERATE.md` §6).

| | 프리필 (s) | 토큰당 (s) | 생성 20 토큰 |
|---|---:|---:|---|
| 상류 torch 2.13.0 | 0.0889 | 0.1025 | 기준 |
| 배송본 | 0.3875 | 0.4310 | 20/20 일치 |
| A 만 | 0.4065 | 0.4317 | 20/20 일치 |
| **A+B** | **0.0890** | **0.1167** | **20/20 일치** |

- **프리필이 상류와 같아졌습니다** (0.0890 대 0.0889). 토큰당은 1.14 배.
- **프리필 로짓 294,912 개가 배송본과 비트 단위로 동일합니다** — `ndiff = 0`.
  상류와의 최대 절대차도 배송본과 똑같은 `5.340576e-05` 로 그대로입니다.
- `A` 만 적용한 줄이 아무것도 바꾸지 못하는 것이 §1 의 증거입니다.

## 6. 남은 벽 — 이름으로

| # | 벽 | 크기 | 무엇이 필요한가 |
|---|---|---|---|
| 1 | **`bfloat16`/`float16` 가중치가 호출마다 `float32` 로 실체화됨** | **이 회차가 없앤 것과 같은 종류의 복사이고, 아직 있습니다.** A+B 를 적용한 뒤에도 같은 모양에서: `lm_head` `(1,6,576)` `float32` **4.75 ms** 대 `bfloat16` **77.84 ms** (16.4×), `float16` 79.33 ms. `gate` 는 0.094 대 1.87 ms (19.9×) | `opmath_in` 의 넓히기는 상류가 하는 것이라 지울 수 없습니다(`docs/BF16.md`). 넓힌 가중치를 **캐시**하거나, 넓히기를 GEMM 안으로 밀어 넣어야 합니다. 수명이 걸린 설계 판단 |
| 2 | **골든이 `aten.matmul.default` 를 안 봄** | `IMPLEMENTED_AWAITING_GOLDEN` 에 있음 (§4.3). 이 문서의 변경이 가장 크게 건드린 커널이 **골든 밖**이었습니다 | `tools/golden/cases.py` 에 케이스 빌더 하나 + `IMPLEMENTED` 로 한 줄 이동 |
| 3 | **왼쪽이 2-D, 오른쪽이 N-D 인 matmul** | 접기가 반대 방향은 안 함. `broadcast_matmul` 이 여전히 왼쪽을 실체화 | 상류의 `should_fold` 반대 갈래. 실측 사용례를 못 찾아 손대지 않았습니다 |
| 4 | **`addmm` 의 bias 브로드캐스트 복사** | `bias.broadcast_as(target).contiguous()` — `lm_head` 에서 196 KB, 가중치 113 MB 대비 0.17% | 작아서 손대지 않았습니다. 이름만 적어둡니다 |
| 5 | **기기 측정 없음** | 전부 호스트 M1 (Accelerate). 안드로이드는 `gemm` 백엔드라 §2 표의 오른쪽 열이 적용됨 | `gemm` 은 마지막 두 차원 스트라이드를 임의로 받으므로 **폴백이 더 적게 발동할 것**으로 보이지만, 재지 않았습니다 |

## 7. 판단이 필요한 것 — 선택지

**비트가 바뀌므로 여기서 임의로 고르지 않았습니다** (`CLAUDE.md` §5.7).
작업 트리에 변경만 있고 **커밋하지 않았습니다.**

| 선택지 | 무엇 | 대가 |
|---|---|---|
| **①  A+B 를 그대로 착지** | 커널 507 중 48 개 비트 변화, 그중 **상류로 후퇴 0 · 개선 35**. SmolLM2 는 비트 무변화 · 3.7~4.4 배 | "골든은 비트 비교" 라는 불변식이 **골든 밖 커널**에서 한 번 흔들립니다. 다만 흔들린 방향이 전부 상류 쪽이고, 골든 2760 · 스키마 4200 · 스모크 197 은 전부 그대로 통과합니다 |
| **② 옵트인으로 가름** (`docs/SDPA.md` §12 선례) | 환경변수/플래그로 켜고, 기본은 배송본 동작 | **기본값이 상류에서 더 먼 쪽**이 됩니다. §0 의 표가 뒤집혀 있었다면 이쪽이 맞지만, 지금은 "느리고 상류와 덜 맞는 쪽" 을 기본으로 두는 것이 됩니다. 그리고 두 경로를 계속 유지해야 합니다 |
| **③ B 만 착지** (접기만, A 없이) | 실모델 이득의 대부분은 B 에서 옵니다 | 접은 뒤의 2-D GEMM 이 다시 `.contiguous()` 를 부르므로 **`lm_head` 복사가 그대로 남습니다.** 성립하지 않습니다 |
| **④ A 만 착지** | — | **성립하지 않습니다.** 3-D 에서 아무 이득이 없고 배치가 있으면 1.87 배 느려집니다 (§1) |

③ 과 ④ 는 측정으로 배제됩니다. 실질 선택은 ① 과 ② 입니다.

먼저 닫아두면 좋을 것: **§6 의 2 번(골든에 `matmul` 케이스 추가)을 이 변경보다 먼저 넣으면**,
①의 유일한 약점("가장 크게 바뀐 커널이 골든 밖")이 사라집니다.
